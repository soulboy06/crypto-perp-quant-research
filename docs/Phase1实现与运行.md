# R010 Phase 1实现与运行

本阶段只在SIG-001上增加“同向最多3仓”。分组参数尚未接入，未启动Phase 2，也未改变金融核心、冻结研究配置或原始结果。

## 名额口径

- 信号时刻按原币种固定顺序处理；统计已持仓和其他待成交的同方向名额，达到3个就拒绝新信号。
- 成交时重新检查，排除当前订单后再加1；最多3个才允许进入原成交逻辑。
- 成交后预留名额转为持仓，原仓位、保证金和止损预算仍由原账本限制。名额不是额外的金融预算。
- 拒单、止损已跨过、实际数量不足、末尾不成交等情况都会释放名额。不因前序拒单而回补同批已拒绝的信号。
- 计划退出在实际成交前仍算已持仓，不提前释放名额。相反方向独立计数，但仍受共享资金和总风险预算限制。

## 命令

标准库实现，Python 3.11+。进入项目根目录后运行：

```powershell
python -B -m unittest discover -s tests -p test_phase1.py -v
python -B scripts/run_phase1.py --prepare-data
python -B scripts/run_phase1.py
```

默认回测窗口固定为2024-07-01至2026-01-01（不含结束点），热身从2024-05-01开始；四个账户为同期SIG-001和3仓候选各跑基础、压力成本。2026历史不请求、不读取。

`--prepare-data`重用已经验收的分区并核对内容哈希；先探测缺失的标记价、资金费和交易价来源，遇到不可修复缺口就停止调度剩余下载。退出码2表示扩展数据尚不完整，不会缩短窗口或填造价格。验收记录位于`artifacts/data/phase1_runs/`，失败也保留，不覆盖旧universe_latest。

确认数据完整后，默认回测才会执行；门槛全部相对同期SIG-001，包括两种成本都要求净收益为正、至少30笔、年化改善≥1个百分点、回撤≤20%、无永久停机/代理强平/歧义、Calmar不降、14天配对循环区块重采样2000次改善区间下限为正。扩展验证也不是独立样本外，正式选模资格始终为false。

## 开发窗口实现诊断

```powershell
python -B scripts/run_phase1.py --scope reproduction
```

该命令明确使用2023-01-01至2024-07-01的既有开发数据，2022年11—12月热身；运行前已固定3仓阈值，不按结果改变参数。两个SIG-001对照的逐笔交易和每日权益必须与保存的SIG001-20261016T045339Z-9b2fe0a6完全相同。

另两个3仓账户只用于发现实现问题和观察规则是否触发。结果无论好坏均保留，不替代扩展验证、不授权Phase 2、不改变旧默认策略。所有数值与停机事件见[开发诊断结果](Phase1_reproduction_结果.md)。

本次诊断中，基础和压力各61笔交易，候选与SIG-001的逐笔交易、每日权益均完全一致；累计-5.82%/-7.12%、折算年化-3.93%/-4.81%、不利路径回撤13.76%/13.80%。候选实际同向持仓最多2个，3仓信号门槛各拒绝2次，未改变最终成交路径。两组仍在2023年11月出现AVAX代理强平与同分钟止损先后歧义并停机；不能把2024年现金期当作持续交易。这说明本批开发路径中3仓上限没有带来收益改进，不能据此降低上限继续寻找好结果。

## 测试范围及限制

7项新增测试覆盖双向同批预留、3个合法订单依次转换、成交时超限重查、失败释放、真实延迟成交拒单、末尾清理，以及限制不触发时两种成本的原成交/退出/权益一致。原SIG-001的4项与十币引擎的6项回归测试也通过。

历史订单与维保规则仍是代理；分钟OHLC不确定同分钟止损与强平先后。当前币池有幸存者偏差，历史开发数据已反复研究，区块重采样也未修正多轮选择偏差。名额上限不等于已证明的收益相关性预算，更不保证提高收益。
